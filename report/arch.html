AlphaZero 五子棋
网络与搜索的结构

一张网络、一棵树、一个回放缓冲区。下面按数据流的顺序把三者拆开画：从 4 个输入平面到策略/价值两个头，从 Node 里的三条扁平数组到一次 PUCT 模拟的四个动作。

一轮训练的闭环

整个系统只有一个循环：自我对弈产数据 → 进环形缓冲 → 采样做梯度 → 新权重发回对弈进程。树搜索是 Python/CPU 密集的，所以对弈拆成多进程；梯度更新只在一张卡上。

输入：4 个平面，永远站在该走子一方

网络从不知道自己执黑还是执白 —— encode() 把棋盘旋转到"我"的视角，所以同一份权重同时是黑棋和白棋。第 4 个平面才把先后手这件事补回去（五子棋先手优势极大，价值头需要它）。

AZNet：一个躯干，两个头

标准 AlphaZero 结构，只有一处刻意的偏离 —— 全部用 GroupNorm 而不是 BatchNorm。

为什么是 GroupNorm

自我对弈是 lockstep 的：256 局同时开局，随着一局局分出胜负，送进网络的 batch 从 256 一路缩到个位数。BatchNorm 的统计量会跟着 batch 规模抖，而且 train() 和 eval() 行为不一致，running stats 会被自我对弈的分布持续污染。GroupNorm 在通道维内做统计，与 batch 大小无关、两种模式下完全相同 —— 一局棋自己算自己的。

训练目标

两项相加，权重都是 1。策略头去拟合搜索给出的访问分布，价值头去拟合这局棋最终的胜负。

p_loss = −Σa π(a) · log softmax(logits)(a) ← 交叉熵，目标是软标签 π = N/ΣN
v_loss = (v − z)² ← z ∈ {−1, 0, +1}，从该局面走子方的视角
loss = p_loss + v_loss
另外每步记一次策略熵 −Σ p log p，用来看网络有没有过早坍缩到少数几个点

π 是搜索的输出而不是网络自己的输出 —— 这就是 AlphaZero 自举的全部机制：MCTS 用当前网络做几百次前向，得到一个比网络原始策略更强的分布，网络再去追这个分布，下一轮搜索因此更准。z 则是那一局真正下完的结果，按存这条记录时轮到谁走来定符号。

采样时才做对称增强

五子棋的规则在 8 种二面体变换下不变，所以每个局面天然有 8 份等价数据。缓冲区只存原始那一份（省 8 倍内存），Buffer.sample() 把一个 batch 切成 8 块，每块套一种变换 —— 向量化、无偏，而且同一个局面在不同 batch 里会以不同朝向出现。π 必须跟着 reshape 成 9×9 一起转，否则策略标签和棋盘就错位了。

树的内存布局

边的统计量不放在子节点里，而是以三条定长数组的形式放在父节点上 —— AlphaZero 的经典做法，选择一步只需要几个 numpy 向量运算，不用遍历子节点对象。

一次模拟的四个动作

选择 → 扩展 → 评估 → 回传。没有 rollout：AlphaZero 用价值头的一个标量代替了传统 MCTS 里随机走到终局的那段模拟。

score(a) = Q(a) + c · P(a) · √(ΣN + 1) / (1 + N(a))
Q(a) = W(a) / N(a)，N(a)=0 时取 0 ← 未访问的边只有先验在推
c = 3.0 ← c_puct，值越大越偏向"先验高但还没试过"的点
非法点：score = −1e9

分母里的 1 + N(a) 让被反复选中的边迅速降温，分子里的 √(ΣN+1) 则随总模拟数增长把探索项整体抬高。前期靠 P 排序，后期靠 Q 定胜负 —— 这一个公式同时是策略先验的入口和搜索的收敛机制。

根节点的三处特殊处理

  • Dirichlet 噪声：只在根上，P ← (1−0.25)·P + 0.25·Dir(0.3)，仅作用于合法点。没有它，网络先验会自我强化，一整轮自我对弈可能只探索同一套开局。
  • 温度采样：前 12 手按 π = N/ΣN 抽样落子，之后直接取访问数最大的点。这是对局多样性的唯一来源 —— 15×15 那次长跑里 TEMP_MOVES=20 超过了实际对局长度，导致白棋每次防守都有失手概率，胜率塌成黑棋 96%。
  • 落子后不丢树：advance(a) 把根换成对应子节点，整棵子树连同 N/W 一起留下来接着用；新根若已扩展，再补一次 Dirichlet 噪声。

批量 lockstep：几百棵树共用一次前向

单棵树的一次模拟只要一个 4×9×9 的前向，H20 上这点计算量纯属浪费。run_sims() 让所有对局同步推进，每一轮模拟把各树的叶子拼成一个 batch 走一次 GPU。

可选的第三个先验来源

A/B 实验里的 rules 臂在扩展时把一个向量化的战术规则先验混进网络先验，冷启动阶段用，之后线性退火掉。

P = (1 − β) · Pnet + β · Prule ← 只在 expand 时混，训练目标完全不变
β(t) = β₀ · max(0, 1 − (t−1)/20) ← β₀ = 0.6，20 轮后两条臂算法完全相同
评估一律强制 β = 0

rule_priors_batch() 用大约 60 个 numpy 操作（与 batch 大小无关）算出成五、封五、活三这类点的权重，所以即使每次批量扩展都调用它也几乎不花时间。这个实验的结论是负面的：9×9 上 320 局对打，rules 得分率 50.9% ± 3.9pp，退火区间内外的差值也在噪声里 —— 在这个规模上测不出规则冷启动的优势。
